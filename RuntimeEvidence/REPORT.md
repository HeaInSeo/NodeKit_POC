# Runtime Requirement Evidence Collector — POC Report (issue #1)

Feasibility evidence for Console Decision 39 "Runtime Requirement Discovery". The output is **not** the canonical Tool Runtime Requirements schema, and nothing here selects a Runtime Profile or touches NodeKit / NodeVault / NodeSentinel / JUMI.

## What was built

- `RuntimeEvidence/` — library. `EvidenceCollector.Collect(root)` walks a local unpacked Tool root and returns an `EvidenceReport`; `ToJson` serialises it.
- `RuntimeEvidence.Cli/` — `dotnet run --project RuntimeEvidence.Cli -- <root>` prints the JSON report.
- `RuntimeEvidence.Tests/` — xunit tests with generated fixtures.
- The three projects are excluded from the Avalonia app (`NodeKit_POC.csproj` `Compile Remove`); the UI is unchanged.

Each evidence item has `kind`, `value`, `source` (where in the artifact, e.g. `elf:PT_INTERP`, `elf:DT_NEEDED`, `shebang:line1`, `posix:mode`) and `method` (`static-read`).

Read-only by construction: files are read with `File.ReadAllBytes`; nothing is executed, fetched, installed or written; symlinks are reported, never followed (so a link out of the root is not read).

### Fixtures (generated by the tests, no third-party binary committed)

1. **Dynamic ELF** `bin/tool` — ELF64 LE x86_64 `DYN` synthesised byte by byte with `PT_LOAD`, `PT_INTERP`, `PT_DYNAMIC` (`DT_NEEDED` ×2, `DT_RUNPATH`, `DT_STRTAB`). Reported: format, architecture, type, interpreter, needed libraries in order, runpath, linkage = dynamic; no unknowns.
2. **Shebang scripts** — `bin/run.sh` (`#!/usr/bin/env python3`): interpreter `/usr/bin/env`, argument `python3`, plus an explicit unknown that the concrete interpreter is resolved through PATH at run time. `bin/wrapper` (`#!/bin/bash -eu`): interpreter `/bin/bash`, argument `-eu`, no unknown.
3. **Unanalysable** — `bin/broken` (ELF magic, truncated header) → `unknown: ELF not fully analysable …`, no fabricated interpreter/needed. `bin/mystery` (execute bit, unknown format) → executable candidate + unknown. `bin/escape` (symlink out of the root) → unknown "symlink not followed". `share/README.txt` (no execute bit, no magic) → not a candidate.

Determinism: two runs on one root, and a run on a second root whose entries were created in the reverse order at a different temp path, produce byte-identical JSON; the report contains no host path, time or environment data. Input immutability: SHA-256, mode, mtime and symlink targets of every entry are unchanged after collection.

## What can be known reliably

- Whether a file is an executable candidate (execute bit or ELF/shebang magic).
- ELF class, endianness, `e_type`, `e_machine` (architecture).
- The requested program interpreter (`PT_INTERP`) — i.e. which dynamic loader path the binary asks for.
- Static vs dynamic linkage as declared by program headers.
- Directly requested shared libraries (`DT_NEEDED`) and search paths (`DT_RUNPATH` / `DT_RPATH`), verbatim and in order.
- Script interpreter path and arguments from the shebang line.

## What cannot be known from these bytes (kept as unknown / not reported)

- Transitive dependencies: `DT_NEEDED` of the needed libraries are not resolved (no library search on any host).
- Minimum glibc / symbol versions (`.gnu.version_r`) — not parsed in this POC.
- Whether a needed library exists in any given Runtime Profile; whether `$ORIGIN` paths resolve inside the artifact.
- The concrete interpreter behind `/usr/bin/env X`, and interpreter versions or language-level dependencies (Python imports, R packages, JVM classpath).
- `dlopen`'d plugins, run-time downloads, environment variables, kernel/CPU feature requirements.
- Non-ELF executables (Mach-O, PE), compressed or packed binaries, archives inside the root — reported as unknown, not guessed.

## Limits of this POC

- Section headers are not used; dynamic information comes from program headers only (the loader's view).
- Whole files are read into memory; very large artifacts were not measured.
- Only ELF32/ELF64 with standard layouts were tested (synthetic x86_64 DYN and one real x86_64 binary). Big-endian and other machines are decoded but not covered by a test.
- POSIX-only tests (execute bits, symlinks).

## Production integration proposal (proposal only — no production code changed)

- An evidence producer could run this static read over the exact pinned Tool artifact and attach the report, keyed by artifact digest, as evidence for whoever owns semantic compatibility (owner still under Architecture Closure).
- Compatibility judgement should consume `elf-interpreter`, `elf-needed`, symbol-version requirements (next step: parse `.gnu.version_r`) and keep every `unknown` as an explicit gap that blocks automatic "compatible" decisions.
- Shebang `env` indirection should be surfaced to the Tool author as a declared-requirement question rather than inferred.
- Profile catalog, DTO/proto fields and NodeVault Resolve changes are out of scope here and need their own decisions.
